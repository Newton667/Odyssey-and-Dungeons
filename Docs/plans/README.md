# Plans

Implementation plans generated by the `ond-planner` agent via the `/ond-plan` command.

## Usage

```
/ond-plan add exhaustion levels to the character sheet
/ond-plan fix the spell slot reset on long rest
```

The planner researches the codebase (in its own context, so it doesn't consume the
main conversation) and writes one plan file here. It never modifies application code.

## Pipeline

```
/ond-research  →  /ond-plan  →  /ond-increment  →  /ond-execute  →  /ond-review  →  commit
```

Plans are sliced into **increments** — ordered, self-contained units of work that each
leave the app buildable and carry their own verification check. Each starts at
`**Status:** not active`.

When you're happy with a plan, run `/ond-increment <path>` to expand it into an execution
document with unit test specs and red/green gates, then `/ond-execute <path>` to build it one
increment at a time. The planner also reads `Docs/research/` and builds on any matching
research instead of re-deriving it.

## Naming

`YYYY-MM-DD-<short-kebab-slug>.md` — e.g. `2026-08-16-exhaustion-levels.md`.

## Status

Each plan carries a **Status** field in its header:

- `Draft` — written, not yet reviewed
- `Approved` — reviewed and ready to implement
- `In progress` — being implemented
- `Done` — shipped (note the version it landed in)
- `Abandoned` — superseded or dropped (keep the file; add a line explaining why)

Update the status as work progresses so this folder stays an accurate record of what
was planned, what shipped, and what was decided against.
